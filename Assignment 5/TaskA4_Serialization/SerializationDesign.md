# A4 Serialization
Mark live JDBC Connection transient: it is a runtime resource and cannot be restored from a file. Mark password transient; preferably persist no plaintext password, only a salted hash in a secure credential store. Persist name, register number and appropriate resident data.
Serializing Hostel traverses its reachable object graph (rooms and residents); reachable objects must implement Serializable. Shared references/cycles are tracked. A non-serializable reachable field causes NotSerializableException unless transient/custom handling is used.
Declare serialVersionUID. If phoneNumber is added while retaining a compatible UID, old streams normally load and the new String field defaults to null. Changing UID or incompatible structural changes can cause InvalidClassException. Use versioned DTOs/migration for long-lived data.
CSV/JSON is portable and human-readable but often larger; Java serialization is compact/easy for object graphs but Java-specific and unsafe for untrusted input. Both save/load n residents in O(n); text needs parsing/conversion. Optional new text fields can be defaulted if parsers ignore unknown/missing fields. Both need version management.
